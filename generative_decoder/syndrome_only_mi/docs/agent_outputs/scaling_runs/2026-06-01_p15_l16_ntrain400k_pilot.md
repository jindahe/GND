# 2026-06-01 p15 L16 ntrain400k Pilot

## Status

`p15_l16_ntrain400k` is still a partial `L=16` pilot.

The completed `train_seed=1,2` results are promising relative to the
`p12_l16_ntrain300k` baseline on the same seeds, but the run is not yet a clean
3-seed result because `train_seed=3` has only completed the `AB` model. The
missing `BA` model has failed repeatedly at CUDA allocation before training
starts.

Current judgement:

- Keep `p15_l16_ntrain400k` as the most promising `L=16` direction.
- Do not report it as a completed 3-seed pilot.
- Do not expand to seeds `4..8` until `train_seed=3` is completed and evaluated.
- The current blocker is CUDA runtime/device allocation, not model performance.

## Latest Retry Outcome

On `2026-06-02`, the missing `train_seed=3` `BA` run was retried through
`scripts/run_codex_gpu.sh` with the same `p15` configuration and
`--skip-existing`.

The sweep reused the existing artifacts as intended:

```text
reuse code: code/tor_n512_d16_k2_seed0
reuse dataset: net/mi_scaling/p15_l16_ntrain400k/datasets/..._AB_xmid.pt
reuse model: net/mi_scaling/p15_l16_ntrain400k/models/..._tseed3_AB_xmid.pt
reuse dataset: net/mi_scaling/p15_l16_ntrain400k/datasets/..._BA_xmid.pt
```

It then failed before `BA` training began, while moving the MADE model to
`cuda:0`:

```text
torch.AcceleratorError: CUDA error: CUDA-capable device(s) is/are busy or unavailable
```

A minimal PyTorch CUDA allocation check showed the same failure mode:

```text
torch 2.10.0+cu128
cuda available True
device count 1
device 0 NVIDIA H100 PCIe
torch.empty(..., device='cuda:0') failed with CUDA-capable device(s) is/are busy or unavailable
```

Inside the GPU wrapper, `nvidia-smi` reported an idle H100 with no running
processes, but PyTorch still could not allocate on the device. This indicates a
CUDA runtime/driver/device state issue rather than a repository or training
configuration issue.
